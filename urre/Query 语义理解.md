# Query 语义理解

在现代搜索与推荐系统中，Query 语义理解（Query Understanding, QU）是整个搜索链路的“大脑”和“翻译官”。它的核心任务是把用户输入的简短、口语化、甚至带有错别字的搜索词（如“适合夏天穿的透气跑步鞋 200左右”），转化为机器能够精准执行的结构化检索条件与语义特征。

一套完整的工业级 Query 语义理解方案通常由以下 **5 个核心模块**串联组成：

**一、 Query 预处理与纠错（Normalization & Spell Correction）**

在理解语义之前，必须先清洗噪声，解决“字面写错了导致搜不到”的问题：

*   **基础清洗**：繁简转换、全半角统一、大小写归一化、去除无意义特殊符号与停用词。

*   **拼写与同音纠错**：

    *   **传统方案**：基于编辑距离（Edit Distance）+ N-gram 语言模型（如 KenLM）+ 拼音混淆集（解决“苹果手鸡” -> “苹果手机”）。

    *   **深度学习方案**：基于 **MacBERT / BART** 的序列标注与 Seq2Seq 纠错模型，能结合上下文纠正同音错别字、形近字以及中英文混杂拼写错误（如“iPhone16 pro max 手机壳”的空格与拼写规范化）。


---

**二、 分词与词权重分析（Tokenization & Term Weighting）**

即便是大模型时代，精确的词法分析依然是倒排索引（如 BM25）和细粒度匹配的基石：

*   **多粒度分词**：结合**精确模式**（切分出最小语义单元，保证高召回）和**搜索模式**（保留长词和实体词，如“北京大学”不切碎，保证高精度）。

*   **词权重（Term Weighting / Core Term Extraction）**：识别 Query 中哪些词是**核心词（必须匹配）**，哪些是**修饰词（可降权或丢弃）**。

    *   _示例_：搜“**华为 Mate60 手机壳 硅胶**”，核心意图词是“**手机壳**”（权重 0.9），品牌修饰是“华为 Mate60”（权重 0.7），材质修饰是“硅胶”（权重 0.4）。如果丢掉“手机壳”，搜出来的全变成几千块的手机，结果就彻底错了。

    *   _实现模型_：通常采用 **BERT + BiLSTM + CRF** 或微调的轻量级 Encoder 模型，输出每个 Token 的重要性概率（0～1）。


---

**三、 命名实体识别与结构化解析（NER & Slot Filling）**

这是将非结构化自然语言转化为**数据库/搜索引擎结构化过滤条件**的关键步骤：

*   **领域实体识别（NER）**：从 Query 中抽取出明确的业务属性槽位（Slots）。

    *   _示例_：“**200元左右**（价格区间） **耐克**（品牌） **男款**（性别） **透气**（功能属性） **跑步鞋**（核心品类）”。

*   **属性归一化（Entity Linking）**：用户搜“钩子运动鞋”，NER 识别出品牌“钩子”，归一化模块将其映射到标准品牌 ID `Brand: Nike`；用户搜“200左右”，映射为结构化区间过滤 `Price: [150, 250]`。

*   **技术选型**：工业界通常采用 **BERT-CRF** 或 **GlobalPointer（全局指针网络，擅长解决嵌套实体）**；对于复杂长尾口语 Query，则引入轻量化大模型（如蒸馏后的 Qwen-1.5B）直接输出 JSON 格式的槽位解析结果。


---

**四、 意图识别与类目预测（Intent Classification & Category Prediction）**

判断用户到底想找哪一类东西，直接决定后续召回要查哪个垂直库或优先展示哪个类目：

*   **类目预测（Query-to-Category）**：将 Query 映射到平台的数千个标准类目树上（输出 Top-K 类目及对应概率）。例如搜“苹果”，预测结果可能是 `数码手机 (0.65)`、`生鲜水果 (0.30)`、`影视音乐 (0.05)`。

*   **意图路由（Intent Routing）**：判断搜索意图的性质，决定触发哪种交互形态。例如：**导航型意图**（直接搜品牌/官网）、**问答/知识型意图**（搜“跑步膝盖疼怎么办”，触发 AI 摘要卡片）、**交易型意图**（搜具体商品型号）。

*   **实现模型**：经典方案为 **TextCNN / FastText**（极快，适合高频头部词）结合 **BERT 多标签分类模型**（擅长长尾语义泛化）。


---

**五、 Query 改写与语义扩展（Query Rewriting & Expansion）**

解决“用户搜的词”和“文档里的词”**字面不一致但语义相同（词汇鸿沟）**的问题：

*   **同义词与上下位词替换**：基于历史点击日志挖掘（共现图谱）或同义词典，将“笔记本”扩展为“Laptop / 手提电脑”。

*   **向量语义改写（Dense Retrieval）**：直接用微调好的双塔模型（如 **BGE / E5**）把 Query 编码成稠密向量，去向量库里召回语义相近的文档，无需字面重合。

*   **大模型生成式改写（LLM Query Rewrite）**：针对复杂、模糊或长尾 Query（如“送给喜欢摄影的男朋友什么生日礼物”），用微调后的 LLM 自动生成 3～5 个高转化率的标准搜索词（如“微单相机”、“相机三脚架”、“镜头清洁套装”）进行多路并发检索。


---

**六、 工业界架构落地策略（快慢双链路协同）**

由于线上搜索对延迟要求极其严苛（整个 QU 阶段通常只有 **10～20 毫秒**预算），工业界普遍采用**“快慢双链路”**设计：

| **链路类型** | **覆盖流量** | **核心技术手段** | **响应耗时** |
| --- | --- | --- | --- |
| **快链路（Cache + 规则/小模型）** | 80% 头部高频 Query | 离线全量预计算存入 Redis 缓存 + 词典树（Trie）+ 量化后的 TinyBERT/FastText | **< 3 ms** |
| **慢链路（深度模型 / 轻量化 LLM）** | 20% 长尾、复杂口语 Query | 实时调用 GlobalPointer NER + 蒸馏版 Qwen/BERT 实时改写与解析（结果异步写回缓存） | **15 ～ 40 ms** |

###### 图搜/搜索视频  Query理解

与纯文本搜索相比，**视频与图片搜索的 Query 理解**最大的不同在于：**用户的意图往往是跨模态、高度视觉化、甚至带有时空动态描述的**（例如搜“一个穿着红色风衣的女人在雨中奔跑的慢镜头”，或者直接上传一张截图加一句“找同款不同颜色的衣服”）。

在现代多模态搜索引擎（如抖音/TikTok 搜索、小红书搜图、Google Lens、视频素材库检索）中，Query 理解方案主要围绕**“跨模态对齐”**与**“细粒度视觉要素拆解”**展开，核心架构分为以下 **5 个关键模块**：

---

**一、 跨模态联合向量编码（Cross-Modal Embedding）**

这是图像/视频搜索的底座，目标是把**用户的文本 Query**、**参考图片**、以及**候选视频/图片**全部映射到同一个语义向量空间中。

*   **文搜图 / 文搜视频双塔编码器**：

    *   **主流模型**：**CLIP / SigLIP（谷歌开源，效果优于 CLIP）**、**BLIP-2**、**InternVideo2**（专门针对视频时序特征优化）。

    *   **工作方式**：用户输入的文本 Query 经过文本编码器（Text Encoder）实时转化为一个 768 维或 1024 维的稠密向量；后端的每张图片或视频关键帧提前通过视觉编码器（Vision Encoder）提取向量存入向量库（Milvus / FAISS），实现毫秒级语义召回。

*   **多模态组合搜索（Composed Image Retrieval, CIR）**：

    *   当用户同时输入**“一张参考图 + 一段修改文本”**（例如上传一张白色沙发图，输入“换成复古绿色的丝绒材质”）时，需要采用多模态融合编码器（如 **BLIP-2 Q-Former** 或基于 **VLM 视觉语言大模型** 的特征融合层），将图像特征与文本修改意图合成为一个新的检索向量。


---

**二、 视觉属性与时空要素拆解（Visual & Spatio-Temporal Slot Filling）**

纯文本的 NER（实体识别）在视频/图片搜索中进化为**“视觉要素解析”**。机器需要把口语化的画面描述拆解成结构化的视觉标签：

*   **静态视觉槽位抽取（针对图片与单帧画面）**：

    *   **主体与类别（Subject）**：猫、跑车、连衣裙。

    *   **细粒度外观属性（Attributes）**：颜色（莫兰迪绿）、材质（磨砂皮）、纹理（格纹）、款式（V领）。

    *   **构图与摄影风格（Style & Composition）**：赛博朋克风、特写镜头（Close-up）、俯拍视角、暗调光影。

*   **动态与时空槽位抽取（专门针对视频搜索）**：

    *   **动作与事件（Action/Event）**：正在做饭、后空翻、汽车漂移（对应视频中的动作识别标签）。

    *   **运镜与剪辑节奏（Camera Motion）**：推镜头（Zoom in）、航拍跟拍、慢动作（Slow motion）、卡点转场。

    *   **声音与 BGM 意图（Audio/Speech）**：用户搜“周杰伦晴天钢琴版配乐的治愈系风景视频”，QU 模块会自动拆出 `音频条件: 晴天(钢琴版)` + `画面条件: 治愈系风景`。


---

**三、 抽象意境的“视觉画面翻译”（Visual Prompt Expansion）**

视频和图片搜索中，用户经常输入**极其抽象、主观的形容词**（如“氛围感”、“高级感”、“松弛感”、“赛博朋克”）。这些词在视频的标题或标签里往往不存在，直接用向量搜也容易偏离。

*   **VLM / LLM 视觉化改写（Visual Grounding Rewrite）**：

    *   利用微调后的大语言模型或视觉语言模型，将抽象的氛围词**“翻译”成具体的客观视觉元素组合**。

    *   _改写示例_：用户输入“**适合深夜听歌的孤独感视频**” -> QU 模块自动扩展改写为具体的画面描述词：`“下雨天的城市夜景、车窗上的雨滴、霓虹灯倒影、一个人走在空旷街道背影、冷色调”`。

    *   扩展后的具体画面描述再送入 SigLIP/CLIP 编码器，召回准确率会大幅提升。


---

**四、 视频的“多维度索引对齐”（Query-to-Video Multi-Channel Routing）**

一段视频包含的信息极其丰富，QU 模块需要判断用户的 Query 到底应该去匹配视频的哪一部分数据，从而进行**多路路由**：

1.  **画面视觉流（Visual Frames / Keyframes）**：匹配视频抽帧后的画面内容（搜“红色跑车”）。

2.  **语音转写流（ASR, Automatic Speech Recognition）**：匹配视频里人物说的话（搜“教你三步做好红烧肉”，画面可能只是人在厨房站着，但台词里有这句话）。

3.  **画面文字流（OCR, Optical Character Recognition）**：匹配视频封面大字、花字字幕、商品包装上的文字（搜某个梗图上的台词，或教程里的 PPT 标题）。

4.  **音频指纹流（Audio / BGM）**：匹配背景音乐旋律或音效。


*   **意图路由策略**：如果 QU 识别出 Query 是**“知识教程/口播观点类”**（如“为什么咖啡会让人困”），系统会大幅提高 **ASR 语音索引**和 **OCR 字幕索引**的召回权重；如果是**“纯视觉美学/壁纸类”**（如“海边日落绝美晚霞”），则完全主导走 **Visual 视觉向量索引**。


---

**五、 以图搜图/视频的 Query 图像理解（Visual Query Understanding）**

当用户的输入本身就是一张图片或一段短视频片段时，QU 针对的是**输入图像本身的处理**：

*   **主体检测与智能抠图（Object Detection & Salient Segmentation）**：

    *   用户拍了一张全身照想搜同款鞋子，如果直接拿整张图去搜，系统可能会匹配到背景里的沙发或衣服。

    *   QU 阶段会先运行目标检测模型（如 **YOLOv8 / Grounding DINO**）和分割模型（**SAM 2**），自动框出画面中的显著主体（如“鞋”、“包”、“上衣”），甚至在前端弹出多个小白点让用户点击选择要搜哪一件，然后裁剪出纯主体送入特征提取器。

*   **质量评估与抗干扰清洗（Quality & De-noising）**：

    *   识别输入图片是否包含水印、黑边、严重模糊或屏幕摩尔纹，在提取特征前进行裁剪去边框或超分增强，避免“搜出一堆同样带有某平台水印的图片”。
