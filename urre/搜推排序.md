# 搜推排序

在现代搜索引擎（如网页搜索、电商搜索、RAG 知识库检索）中，面对海量数据，通常不会只用一个排序模型，而是采用==“漏斗式多阶段排序架构”==。从初筛到最终展示，主要分为**召回（Retrieval）**、**粗排（Pre-ranking）**、**精排（Ranking）**和**重排（Re-ranking）**四个阶段，每个阶段使用的核心模型各不相同。

###### 特征工程

*   **数值**：归一化 / 分桶 / log 变换 / 截断，处理长尾

*   **类别**：one-hot、目标编码（需平滑+防泄漏）、hash、embedding

*   **文本**：分词、n-gram、TF-IDF、词向量、BERT/双塔向量

*   **交叉**：A×B 组合、统计类 CTR、笛卡尔后降维

*   **时间/序列**：时间窗统计、衰减加权、行为序列 pooling / Attention


1. Query 侧 长度、分词数、是否含实体/品牌/型号、意图分类（导航/信息/交易）、Query 热度与历史 CTR、时效性词（"今天""2026"）、改写/同扩展词、点击熵（意图是否分散）。 2. item 侧 标题/正文长度、内容质量分、权威度/来源等级、发布时间与新鲜度、类目、历史 CTR/CVR、收藏加购、投诉/作弊惩罚分、内容 embedding。

3.Query–item 相关性

例子

字面匹配: BM25、TF/IDF、词覆盖率、短语精确匹配、编辑距离

字段命中: 标题命中 > 锚文本 > 正文；命中位置、命中次数

语义匹配: 双塔向量余弦、BERT cross-encoder 相关性分

结构化匹配: 类目/品牌/地域/价格区间/时间是否对齐

统计交叉: q-i 共现点击、query 类目 × item类目 的平滑 CTR

4.用户 / 上下文 / 行为 用户画像与长期兴趣标签、历史点击/搜索序列（短期 session 权重更高）、设备、时段、地理位置、曝光位置 position（既是强特征也是偏差源）。

**一、 召回阶段（Retrieval）：从亿级库中快速捞出千级候选**

这一阶段追求**极致的响应速度**（毫秒级），核心模型主要分为传统字面匹配与现代语义向量两类：

*   **传统词法模型（Sparse Retrieval）**：

    *   **BM25**：工业界最经典的基于词频（TF）和逆文档频率（IDF）的统计模型，对专有名词、型号、精准字面匹配极其有效。

*   **双塔向量模型（Dense Retrieval / Bi-Encoder）**：

    *   **代表模型**：**DPR、BGE (BAAI General Embedding)、E5、Contriever**。

    *   **原理**：使用两个独立的编码器（如 BERT），分别将 Query 和文档（Document）离线压缩成一个固定维度的向量。线上搜索时，只需计算 Query 向量与文档向量的**余弦相似度或内积**（配合 FAISS / Milvus 向量数据库），速度极快。

*   **学习型稀疏模型（Learned Sparse Retrieval）**：

    *   **代表模型**：**SPLADE、ColBERT（Late Interaction，延迟交互）**。

    *   **原理**：结合了双塔的速度与细粒度匹配能力。例如 ColBERT 会保留 Query 和文档中每个 Token 的向量，在检索时计算最大相似度（MaxSim），精度远超普通双塔。


---

**二、 精排阶段（Ranking / Re-ranking）：对百级候选进行高精度打分**

召回几百条结果后，算力允许使用更复杂的模型让 Query 和文档进行**深度特征交叉（Deep Interaction）**，这是决定搜索相关性最核心的环节：

*   **交叉编码器（Cross-Encoder / Reranker）**：

    *   **代表模型**：**BERT-Reranker、BGE-Reranker、Cohere Rerank、MonoT5**。

    *   **原理**：把 Query 和文档拼在一起（`[CLS] Query [SEP] Document [SEP]`）直接喂入 Transformer 模型。利用自注意力机制（Self-Attention），让 Query 的每一个字都能和文档的每一个字直接计算关联度，最后输出一个相关性得分。**精度极高，但计算量大**，只能用于排在最前面的几十到几百条结果。

*   **传统集成树模型（GBDT 家族）**：

    *   **代表模型**：**LambdaMART、XGBoost、LightGBM**。

    *   **原理**：在商业搜索（如淘宝、Google）中依然占据重要地位。它们擅长处理海量人工特征与统计特征（如历史点击率 CTR、销量、文档新鲜度、PageRank 权重），并通过 **Pairwise（成对）** 或 **Listwise（列表）** 损失函数直接优化 NDCG 等排序指标。

*   **深度推荐/搜索融合模型**：

    *   **代表模型**：**DeepFM、DIN（深度兴趣网络）、DCN（深度交叉网络）**。

    *   **原理**：主要用于电商、短视频等个性化搜索，将 Query 语义特征、用户历史行为序列与商品特征进行高阶交叉，同时预测点击率（CTR）和转化率（CVR）。


---

**三、 大模型时代的新范式（LLM-based Ranking）**

随着大语言模型（LLM）的发展，排序模型正在向更强的推理与生成能力演进：

*   **LLM Listwise 重排（如 RankGPT、RankZephyr）**：直接把 Query 和前 20 篇候选文档的摘要一次性塞进大模型的上下文窗口，利用大模型的强逻辑推理能力，直接输出重排后的文档编号列表（如 `[3] > [1] > [5]...`）。

*   **生成式检索（Generative Retrieval，如 DSI / TIGER）**：打破“先建索引再匹配”的传统，直接训练一个端到端的 Seq2Seq 大模型，输入 Query，模型像生成文本一样直接吐出最相关文档的 **Semantic ID（语义编码）**。


**四、 主流模型选型对比**

| **阶段** | **代表模型** | **交互方式** | **计算耗时** | **核心优缺点** |
| --- | --- | --- | --- | --- |
| **初级召回** | **BM25** | 词面精确匹配 | 极快（<5ms） | 抗噪强、精准匹配好，但无法理解同义词 |
| **语义召回** | **BGE / E5 (双塔)** | 句向量点积 | 快（10ms内） | 懂语义泛化，但压缩成单向量会丢失细节 |
| **折中检索** | **ColBERT** | Token级延迟交互 | 中等（20~50ms） | 兼顾速度与细粒度匹配，但向量存储开销大 |
| **高精度精排** | **BGE-Reranker (Cross-Encoder)** | 全量交叉注意力 | 较慢（百毫秒级） | 语义理解天花板，但无法直接面对海量库 |
| **商业多目标** | **LambdaMART / DeepFM** | 特征交叉 + 树/MLP | 快（10~30ms） | 极度适合融合点击率、业务权重与个性化特征 |

*   将 **Query 文本语义**、**传统统计特征**（如销量、CTR、价格）、**类别特征**（如品牌、类目 ID）以及 **用户偏好特征**（如历史点击序列、用户画像）融合到同一个排序模型中，工业界主要有**“两阶段特征解耦（主流方案）”**和**“端到端联合建模”**两种架构。


以下为你拆解具体的融合方法与架构设计：

---

###### 传统特征/偏好和quey 交叉融合方式

**一、 核心前提：所有特征的“向量化对齐”**

在送入同一个神经网络之前，不同模态和量纲的特征必须先转换成统一的**稠密向量（Dense Embedding）**：

*   **Query 与文档文本特征**：通过预训练语言模型（如 BERT、BGE）提取语义向量，或直接计算出 **Query-Item 语义匹配分（作为强交互特征）**。

*   **类别特征（Sparse / ID 类）**：如用户 ID、商品类目、品牌。通过 **Embedding Lookup Table（嵌入查找表）**，将高维稀疏的 One-Hot 编码映射为低维稠密向量（例如 16 维或 64 维）。

*   **传统数值特征（Dense / 统计类）**：如价格、历史点击率（CTR）、销量、BM25 文本匹配分。

    *   _处理技巧_：不能直接拼接！通常先做**归一化（Log 变换、Z-Score）**，或采用**分桶离散化（Bucketing）后再查 Embedding 表**，甚至使用连续特征嵌入层（如 AutoDis），使其量纲与语义向量对齐。

*   **用户偏好特征（行为序列类）**：如用户过去 30 天点击/购买过的商品 ID 序列。通过 **序列聚合层**（如 Mean Pooling、Self-Attention 或 **DIN 靶向注意力机制**）压缩成一个固定长度的“当前意图兴趣向量”。


---

**二、 工业界两大主流融合架构**

**方案 1：两阶段特征解耦（语义特征化 + 深度精排模型）—— 最稳健、延迟最低**

这是目前大厂搜索精排（如电商、短视频搜索）最主流的落地方式。直接把大模型（BERT）和业务特征塞进一个端到端模型，线上推理延迟会爆炸，因此采用**“大模型提特征 + 精排模型做交叉”**的策略：

1.  **第一层（语义特征提取）**：提前用微调好的 Cross-Encoder 或双塔模型，算出当前 `Query` 和候选 `DItem` 的**语义相关性得分**（甚至细分为标题匹配分、类目预测匹配分等 5～10 个数值特征 如（标题、摘要、标签、品牌、正文））。

2.  **第二层（多特征大融合）**：将上述**语义匹配分**，与**传统统计特征**、**类别 Embedding**、**用户历史序列特征**全部拼接（Concatenate）成一个超长向量。

3.  **第三层（高阶特征交叉网络）**：将拼接后的向量送入专门的深度学习精排模型：

    *   **DCN-v2（Deep & Cross Network）**：显式地做特征之间的多项式交叉（例如自动学习“Query搜‘苹果’ + 用户偏好‘数码’ + 价格 > 5000”的组合权重）。

    *   **DIN / DIEN（深度兴趣网络）**：用当前搜索的 `Query` 和候选商品去作为 Query（Attention 机制里的 Q），对用户的历史行为序列（K, V）做注意力加权。**比如用户搜“跑鞋”，模型会自动放大他历史行为里“运动品牌”的权重，忽略他昨天买“牛奶”的记录。**


**方案 2：端到端统一表示（文本化 Prompt + LLM / 联合双塔）—— 泛化能力最强**

如果算力充足（例如 QPS 不高的企业级搜索、高客单价垂类推荐），可以把所有非文本特征“翻译”成自然语言或特殊 Token，喂入同一个 Transformer：

*   **特征文本化（Feature-to-Text）**：把结构化特征直接拼成一段描述文本。

    *   _输入示例_：`[Query] 降噪耳机 [用户偏好] 25岁男性，近期常看索尼、Bose，偏好高端数码 [商品信息] 索尼 WH-1000XM5，类目：影音数码，月销5000+，好评率98%`

*   **联合编码打分**：直接将这段拼接后的超长文本送入微调后的 **BERT / DeBERTa 或轻量化 LLM（如 Qwen-1.5B/7B）** 中，利用强大的自注意力机制让每个字和每个业务属性自由交互，最后通过一个线性层（MLP）输出排序分数。


---

**三、 关键工程细节：避免特征“打架”**

把语义特征和统计特征放进同一个模型时，极易出现**“统计特征霸占主导权”**（模型只看销量和历史 CTR，完全无视 Query 语义相关性，导致搜什么都推爆款）。工程上通常这样解决：

*   **Dropout / 特征掩码（Feature Dropout）**：在训练时随机把“历史点击率、销量”等强统计特征置零，逼迫模型去学习 Query 语义和用户偏好的深层关系。

*   **多任务学习（MMoE / PLE）**：设置多个预测头（Multi-Head），一个头专门预测**文本相关性（Relevance）**，另一个头预测**点击率/转化率（CTR/CVR）**，最后通过公式融合（如 `Final_Score = Relevance^α × CTR^β`），确保不相关的爆款绝对排不到前面。


---

**四、 架构选型总结**

| **融合方案** | **代表模型** | **线上推理耗时** | **适用场景** |
| --- | --- | --- | --- |
| **语义提分 + 深度交叉网络** | **BGE + DCN-v2 / DIN** | 极快（10～20ms） | 高并发电商搜索、信息流搜索（最推荐） |
| **树模型融合** | **BERT特征 + LambdaMART** | 快（<10ms） | 数据量中小（百万级以下）、特征工程成熟的业务 |
| **特征文本化 + 大模型端到端** | **DeBERTa / Qwen-Reranker** | 较慢（50～200ms） | 复杂长尾 Query、重推理的垂类知识库/专家搜索 |

###### 多socre融合公式

**1. 乘性幂次加权公式（工业界最主流）**

这是目前电商（如淘宝、京东）、短视频和信息流搜索中最常用的公式。它通过幂指数（\(\alpha, \beta, \gamma\)）来控制各个目标的敏感度，利用乘法保证**“一票否决”**机制（只要相关性极低，哪怕点击率再高，总分也会趋近于 0）。

\(\text{Score}=\left(S\_{\text{rel}}\right)^{\alpha }\times \left(p\_{\text{CTR}}\right)^{\beta }\times \left(p\_{\text{CVR}}\right)^{\gamma }\times \left(\text{Price}\right)^{\delta }\)

*   **各参数含义**：

    *   \(S\_{\text{rel}}\)：相关性模型输出的概率值（0～1）。

    *   \(p\_{\text{CTR}}, p\_{\text{CVR}}\)：精排模型输出的点击率与转化率（0～1）。

    *   \(\alpha, \beta, \gamma\)：超参数权重（通常在 0.5 到 2.0 之间）。例如在搜索场景中，为了死守相关性底线，通常会把 \(\alpha \) 设得较大（如 \(\alpha = 1.5, \beta = 1.0, \gamma = 0.8\)）。

*   **工程防坑技巧（平滑偏置）**：
    为了防止某个极小值（如 \(0.0001\)）导致整体分数崩盘，通常会给每个分数加上一个平滑常数偏置 \(b\)：
    \(\text{Score}=\left(S\_{\text{rel}}+b\_{1}\right)^{\alpha }\times \left(p\_{\text{CTR}}+b\_{2}\right)^{\beta }\times \left(p\_{\text{CVR}}+b\_{3}\right)^{\gamma }\)

---

**2. 对数线性加权公式（Log-Linear / 便于调参）**

上面乘性公式的等价变形。两边取对数（\(\ln \)）后，乘法就变成了加法，非常方便在工程中通过线性回归或网格搜索（Grid Search）来求解最优权重：

\(\text{Score}=w\_{1}\ln (S\_{\text{rel}}+\epsilon )+w\_{2}\ln (p\_{\text{CTR}}+\epsilon )+w\_{3}\ln (p\_{\text{CVR}}+\epsilon )+w\_{4}\ln (E\_{\text{time}}+\epsilon )\)

*   **核心优势**：

    *   数学上完全等价于幂次连乘，但**数值稳定性更好**（避免多个小数连乘导致浮点数下溢）。

    *   在业务调参时，增大 \(w\_{1}\) 就能直观地提升相关性在排序中的话语权。

**3. 排序位次融合公式（RRF, Reciprocal Rank Fusion）**

当你的多个模型**分数不在同一个量纲**（比如模型 A 是 BM25 分数，范围 `0 ~ 35`；模型 B 是向量余弦相似度，范围 `-1 ~ 1`；模型 C 是精排模型 Logit，范围 `-10 ~ +10`），直接做加减乘除会严重失真。此时最稳健的做法是**不看绝对分数，只看各自排第几名**。

\(\text{Score}\_{\text{RRF}}(d)=\sum \_{i=1}^{M}\frac{w\_{i}}{k+\text{rank}\_{i}(d)}\)

*   **各参数含义**：

    *   \(M\)：参与融合的模型数量。

    *   \(\text{rank}\_i(d)\)：候选文档 \(d\) 在第 \(i\) 个模型中的排名位次（第 1 名就是 1）。

    *   \(w\_{i}\)：第 \(i\) 个模型的权重（默认可设为 1）。

    *   \(k\)：平滑常数，**工业界标准经验值为 \(k = 60\)**。它的作用是防止排名第 1 的结果得分过高（\(1/1 = 1\)），从而抹平头部排名的过度差距，让“在多个模型中都排前 5”的结果胜出。

*   **适用场景**：**RAG 混合检索**（BM25 + 向量检索融合）、多路召回合并、不同量纲模型快速上线冷启动。

**4. 线性加权与归一化公式（Min-Max / Z-Score + 线性相加）**

如果多个模型都代表同一类指标（例如都是不同角度的相关性打分），可以通过归一化拉齐量纲后直接线性相加：

\(\text{Score}=w\_{1}\cdot \text{Norm}(S\_{1})+w\_{2}\cdot \text{Norm}(S\_{2})+w\_{3}\cdot \text{Norm}(S\_{3})\)

*   **常用的归一化函数 \(\text{Norm}(x)\)**：

    *   **Min-Max 归一化**：\(\frac{x-x\_{\min }}{x\_{\max }-x\_{\min }}\)（将当前 Query 下的所有候选分数压缩到 `[0, 1]` 之间）。

    *   **Z-Score 标准化**：\(\frac{x-\mu }{\sigma }\)（减去均值除以标准差，抗异常值能力比 Min-Max 更强）。

**五、 进阶：公式里的权重（\(\alpha, \beta, w\_i\)）怎么定？**

手工拍脑袋调超参数往往耗时耗力，工业界通常采用以下三种方法自动寻优：

1.  **网格搜索 / 贝叶斯优化（Bayesian Optimization）**：在离线验证集上，设定主目标（如 GMV 或有效点击率）和约束条件（如相关性降幅不超过 0.5%），自动搜索最优的 \(\alpha, \beta, \gamma\) 组合。

2.  **进化算法（CEM 交叉熵法 / 遗传算法）**：在线上分配小流量（如 1% 流量），让算法自动探索不同权重组合的线上 AB 实验表现，动态收敛到全局最优权重。

3.  **端到端学习融合层（Meta-Ranker）**：直接把多个模型的输出分数作为特征，再训练一个极轻量的**单层 MLP 或逻辑回归（LR）**，用最终业务目标（如是否下单、是否长期留存）作为 Label 进行端到端学习。
