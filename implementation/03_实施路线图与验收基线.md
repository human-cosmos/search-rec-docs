# 实施路线图与验收基线

> **文档层级：** 实施计划  
> **上位文档：** [00 平台总体架构](../00_架构设计总纲.md)  
> **实施支撑：** [API 与数据契约](01_API与数据契约.md)、[技术选型与服务部署](02_技术选型与服务部署.md)  
> **状态：** 建议排期，不构成交付承诺

## 1. 总体实施策略

实施顺序遵循：

```text
平台与契约
  → 视频检索
  → 任务上下文推荐
  → 创作规划与素材组合
  → 时间线、渲染与评估
  → 推荐升级与跨领域扩展
```

三条核心闭环需要尽早跑通：

1. 检索闭环：自然语言 Query → Query Understanding → 多路召回 → 排序 → 结果与证据。
2. 推荐闭环：项目任务上下文 → 推荐召回与排序 → 用户采用 → 反馈归因。
3. Agent 闭环：用户目标 → Plan → Tool/Workflow → Artifact → 用户确认与反馈。

## 2. 阶段计划

能力里程碑以 [`00_架构设计总纲.md`](../00_架构设计总纲.md) §10 的 A–D 为准；本节 0–5 是工程迭代。对照关系：

| 工程迭代 | 能力里程碑 | 说明 |
|---|---|---|
| 阶段 0 | 为阶段 B 准备治理底座 | 契约、Runtime 对象、职责矩阵和选型 PoC |
| 阶段 1–2 完成 | 阶段 A 退出 | 阶段 1 含 Search，阶段 2 含 Recommend 与 Similar；二者都具备独立链路后，才算阶段 A 退出 |
| 阶段 3–4 | 阶段 C | 创作工作流、素材组合、时间线、渲染与评估 |
| 阶段 5 | 阶段 D | 推荐升级、规模化与跨领域 |

Explore 在 `01` 中仍是一等能力，但**不作为阶段 0–2 的强制退出项**，上线阶段可延后，待规划拍板。

### 阶段 0：架构与契约 PoC

建议周期：1—2 周。

主要工作：

- AgentScope Java 2.0 嵌入 Spring Boot。
- 实现最小 Video Director Agent。
- 验证 Agent Tool → URRE API。
- 冻结 Video、Shot、Segment Schema。
- 建立真实样本视频和相关性标注集。
- 对比 Elasticsearch/OpenSearch、Vespa、Milvus。
- 验证解析、镜头切分、Embedding 和索引。
- 定义 Session、Plan、Task、Checkpoint、Artifact 的持久化边界。
- 冻结 Platform Agent、Video Director、Search Planner 和 Recommendation Strategy 的职责矩阵。

交付：

- 技术 PoC 与 ADR。
- AgentScope 接入样例。
- Video Domain SPI。
- Search API 契约。
- 数据契约、事件字典和初步评估报告。

退出标准：

- 自然语言 Query 能通过 Agent Tool 到达 URRE。
- 能返回真实镜头级候选和时间区间。
- 请求、候选、结果和行为可关联。
- 关键组件选型有真实数据支撑。

### 阶段 1：Video Search MVP

建议周期：2—4 周。

主要工作：

- Video、Shot、Segment 基础模型和索引。
- 视频入库、元数据提取、缩略图和镜头切分。
- BM25 + Text Vector 混合召回。
- 条件允许时加入基础视觉向量召回。
- RRF、规则过滤、基础排序和去重。
- 搜索结果展示、预览和反馈。
- 简单请求直接调用 Search API，复杂 Query 才使用 Search Planner。
- 固化 SearchPlan 的适用范围、Schema 校验和失败回退。

交付：

- Video Search API。
- 镜头级搜索。
- Agent 辅助搜索。
- 检索评测集和基线报告。

退出标准：

- 普通搜索不依赖 Agent。
- 复杂查询可生成并校验 SearchPlan。
- 所有结果可定位源视频和时间区间。
- 租户、权限和 Rights 过滤可靠。

### 阶段 2：Project-aware Recommendation

建议周期：2—4 周。

主要工作：

- User、Project、Task 和 Session Context。
- Recommendation Strategy 负责场景、目标、约束和策略 ID，Recommendation Service 负责实际召回与排序。
- Home、Project、Shot、Search Complement、Similar 和 Continue Exploration 场景。
- 内容召回、协同过滤基础版和项目上下文召回。
- 多路融合、多样性和去重。
- 曝光、点击、预览、下载、收藏、时间线采用反馈。
- 推荐离线评估、策略版本和 A/B 基础。

交付：

- Recommendation API。
- 当前项目主动推荐。
- 行为反馈闭环。
- 推荐质量看板。

退出标准：

- 推荐能区分长期兴趣与当前任务。
- 曝光和采用归因完整。
- 推荐结果具备多样性、可解释依据和版本信息。
- Recommend 与 Similar 独立接口可用。Explore 不是本阶段强制退出项。

### 阶段 3：Creation Workflow 与 Creative Composition

建议周期：3—5 周。

主要工作：

- VideoIntent、Task Brief、CreativeBrief、Storyboard 和 ShotPlan。
- 多镜头并行 Search/Recommend。
- Material Assignment 和 Creative Composition。
- 素材覆盖、风格一致性、重复度和时长约束评估。
- 用户 Curation、Artifact 版本和依赖失效。
- Task 进入 `Waiting`（含原因）、恢复、取消和检查点；不设独立 `Paused` 状态。

交付：

- Video Creation Workflow。
- 创作型素材组合推荐。
- 分镜、素材分配和用户审核工作台。
- 任务状态和事件流。

退出标准：

- 用户可以从创作目标生成结构化分镜。
- 系统能为每个镜头产生候选并形成组合。
- 用户修改后能从对应阶段继续，不重建无关产物。

### 阶段 4：Timeline、Render 与 Evaluation

建议周期：3—5 周。

主要工作：

- EditDecision Schema。
- Timeline IR、Validator 和 Compiler。
- NLE Adapter 和 FFmpeg Preview Worker。
- 独立 Evaluator。
- 人工确认、审批和导出。
- 最终保留、替换和导出反馈。

交付：

- 可预览时间线草稿。
- 编辑器适配接口。
- 评估报告。
- 完整视频创作闭环。

退出标准：

- Timeline IR 可验证、可重建、可编辑。
- 渲染失败可以定位与恢复。
- 高风险导出具有审批和审计。
- 最终采用反馈能回流 URRE 和 Agent 评估。

### 阶段 5：推荐升级、规模化与跨领域

主要工作：

- Two-Tower 召回、DNN Ranker、序列推荐和多任务排序。
- 学习型重排、组合优化和模型灰度。
- 更大规模 Shot/Segment 索引。
- 外部互联网素材接入。
- 多租户容量、成本、SLA 和故障演练。
- Product Domain：商品、SKU、供应商、市场、机会和选品工作台。
- Marketing Domain：Campaign、Creative、Audience、Channel、预算和投放审批。
- 商品发现 → 视频创作 → 广告投放的跨领域流程。

Product Domain 的首版核心实体包括：

- `Product`、`SKU`、`Supplier`、`Listing`
- `Category`、`Market`、`Audience`、`Trend`
- `Opportunity`、`SourcingRecord`

商品评估需要结合语义和属性、类目、价格带、市场需求、趋势、竞争强度、供应链稳定性、采购成本、物流、毛利、质量与合规风险。相似品、替代品、互补品和受众衍生品应作为不同关系类型，不统一压成相似度。

Marketing Domain 的首版核心实体包括：

- `Campaign`、`AdGroup`、`Creative`
- `AudienceSegment`、`Channel`、`Placement`
- `PerformanceMetric`、`Budget`、`Experiment`、`OptimizationAction`

营销评估关注 CTR、CVR、CPA、ROAS、预算效率、创意疲劳、受众覆盖和实验提升。预算调整、广告启停、素材发布等高影响操作必须经过 Policy Gateway、审批和审计。

退出标准：

- 真实线上指标相较基线稳定提升。
- 成本、延迟和质量可量化。
- 视频与商品共用 URRE 核心 API 和基础设施。
- 新领域通过 Domain Pack 扩展，不修改视频业务逻辑。
- 跨领域共享任务、Artifact 引用和审计，但领域评分和权限保持隔离。

## 3. 首期 MVP 范围

### 3.1 必须实现

- AgentScope Java 2.0 + Spring Boot。
- Video Domain Pack SPI 和注册机制。
- Video、Shot、Segment 基础 Schema。
- 视频元数据、镜头切分和缩略图。
- BM25 + 文本向量召回。
- 基础融合、过滤、排序和去重。
- Search、Recommend、Similar 和 Feedback API。Explore 接口可在本阶段之后补齐，不作为阶段 0–2 / 首期 MVP 强制退出项。
- Video Director 最小版本。
- 项目与任务上下文最小版本。
- 搜索结果预览和反馈事件。
- 租户、权限和 Rights 过滤。
- `request_id`、`task_id`、`agent_run_id` 全链路关联。
- 基础离线评测集。

### 3.2 可以随后实现

- 大规模多 Agent Team。
- 完整 Two-Tower、序列推荐和生成式推荐。
- 大规模知识图谱。
- 自动持续训练和自动上线。
- 复杂组合优化模型。
- 全自动剪辑和发布。
- 多编辑器深度双向同步。
- 商品和营销领域完整业务流。

### 3.3 MVP 不可妥协项

即使功能范围缩小，以下能力必须从第一天建立：

- 数据契约。
- 租户与权限隔离。
- Rights / Provenance。
- 索引和模型版本。
- 任务可追踪与恢复。
- 事件归因。
- 有副作用操作的幂等和审计。

## 7. 验收指标基线

初期先建立人工标注集和线上基线，再冻结阶段目标。可测阈值、示例分数和生产门槛以本实施文档为准；`01` / `02` / `03` 的原则验收不另给生产门槛，示例分数不是生产门槛。

阶段退出标准与主文条款的对应关系：

| 实施关注点 | 对应主文 |
|---|---|
| Search / Recommend 独立链路、简单请求直达 URRE | `01` §12、`00` §2.1 / §10 阶段 A |
| 四类能力语义独立、Explore 上线阶段 | `01` §12 第 1 条、`00` §10 对照表 |
| Task 状态、预算耗尽进入 `Waiting`、审批与恢复 | `02` §4.2 / §10、`02` §13 |
| ShotPlan、Material Assignment、Creative IR | `03` §6、`03` §15 |
| Rights 硬门禁与质量门禁 | `00` ADR-09、`03` §9 / §10 |

必须监控：

- Search 和 Recommend 的 P50/P95/P99。
- 召回通道成功率和超时率。
- Recall@K、NDCG@K、MRR。
- 零结果率和搜索成功率。
- 推荐覆盖率、多样性、新颖性和采用率。
- 任务素材准备耗时。
- ShotPlan 覆盖率和 Assignment 接受率。
- Agent Tool 成功率、平均步骤数和任务成本。
- Workflow 恢复率。
- Timeline 校验失败率和渲染失败率。
- 最终导出率和成片保留率。
- Rights / 租户权限过滤违规数，目标为 0。

离线指标不能替代线上业务结果，应通过 A/B、分流实验和人工评价验证。

## 8. 主要风险

| 风险 | 后果 | 应对 |
|---|---|---|
| 过早追求全领域通用 | 领域需求失真、交付拖延 | 先用视频验证，再抽象稳定共性 |
| 只按 Video 建索引 | 无法精确找到镜头和片段 | Video/Shot/Segment 三级模型 |
| 超级实体模型 | 模型混乱、字段爆炸 | 公共元信息 + 独立领域 Schema |
| 所有请求都经过 Agent | 延迟和成本上升 | 任务复杂度分级，简单请求直达 API |
| LLM 逐条遍历全量素材 | 成本高、不稳定 | URRE 召回排序，LLM 只处理小候选集 |
| 只使用用户画像 | 推荐不贴合当前创作 | 引入 Project、Shot 和 Task Context |
| 只看 CTR | 下载不等于采用 | 追踪时间线采用和最终保留 |
| 只推荐单条素材 | 无法完成整体创作 | Creative Composition |
| Agent 直接生成 FFmpeg 命令 | 执行风险和不可复现 | Timeline IR + Compiler |
| Scratchpad 代替数据库 | 状态不一致 | 业务 DB + Artifact Store |
| 多 Agent 过度拆分 | 协作复杂、成本上升 | 单主 Agent + 按需委派 |
| 长任务不持久化 | 中断后无法恢复 | Task DB + Workflow Checkpoint |
| 生产者自评 | 质量偏差 | 独立 Evaluator |
| 外部素材版权不清 | 法律和业务风险 | Rights Metadata + 硬过滤 |
| 不同模型分数直接相加 | 排序失真 | 分数校准、归一化和学习排序 |
| 反馈缺少归因 | 无法训练和归因 | request_id、候选集和位置全链路关联 |
| 组件动态加载失控 | 安全与兼容风险 | 注册制、白名单、校验和版本控制 |

## 9. 关键实施决策（IMPL-ADR）

本表是实施决策，编号为 `IMPL-ADR-01`–`IMPL-ADR-12`，与 `00` §9 的架构 ADR（`ADR-01`–`ADR-12`）分属不同编号空间。引用 `00` 的决策时必须写「`00` ADR-xx」。

| ID | 决策 | 后果 | 与 `00` 的关系 |
|---|---|---|---|
| IMPL-ADR-01 | AgentScope Java 2.0 作为 Agent Runtime | 参考 Python 项目主要复用设计模式或接入独立模型服务 | 落实 `00` ADR-04 / ADR-05 的 Runtime 实现选型；技术方向权威见 `02` 文首 / §12 |
| IMPL-ADR-02 | Agent 与 URRE 解耦 | Agent 不直接连接索引和向量数据库 | 落实 `00` ADR-01 |
| IMPL-ADR-03 | Video / Shot / Segment 三级模型 | 索引、引用和反馈必须支持层级映射 | 落实 `00` ADR-03 与 `00` §7.1 |
| IMPL-ADR-04 | Creative Composition 独立能力 | 需要 Storyboard、ShotPlan（内嵌 Material Requirements）和 Material Assignment | 落实 `00` ADR-03 在视频域的创作组合；对象关系以 `03` §6 为准 |
| IMPL-ADR-05 | LLM 决策与媒体执行分离 | 需要 Timeline IR、Validator、Compiler 和 Worker | 落实 `00` ADR-08 |
| IMPL-ADR-06 | 业务状态独立于 Agent Session | Task、Project、Artifact 是业务事实源 | 落实 `00` ADR-04 |
| IMPL-ADR-07 | 人机协作优先于全自动化 | 工作流必须支持 `Waiting`（`awaiting_user` / `awaiting_external` / `budget_exhausted`）与审批；不设独立 `WAITING_USER` 或 `Paused` 状态 | 落实 `00` ADR-04、`00` ADR-10；状态集以 `02` §4.2 为准 |
| IMPL-ADR-08 | 证据随候选返回 | Agent 和用户可核验命中内容与时间位置 | 落实 `00` ADR-07 |
| IMPL-ADR-09 | 固定流程优先，动态规划受控 | 简化测试、延迟和成本控制 | 落实 `00` ADR-05 |
| IMPL-ADR-10 | Rights / Provenance 为硬约束 | 版权不明时限制自动交付或发布 | 落实 `00` ADR-09 |
| IMPL-ADR-11 | Agent / Tool / Service / Workflow 先判定职责形态 | 避免重复启动自治 Agent，保持确定性执行边界 | 落实 `00` ADR-11 |
| IMPL-ADR-12 | Qdrant 作为默认向量数据库，Milvus 为规模化备选 | 文本/视觉向量召回与 Payload 硬过滤使用 Qdrant；数亿级向量、高写入或资源隔离形成明确需求后，经 PoC 和 ADR 重新评估 Milvus；两种实现均通过 `VectorStorePort` 隔离 | 落实 `00` ADR-01；选型与切换条件见 `01` §5.5、技术栈见 `02` §2.1 |

## 10. 推荐实施结论

先跑通“自然语言 → 镜头级检索 → 项目推荐 → 素材组合 → 用户确认”的核心链路，再扩展完整时间线、渲染、跨领域和多 Agent 协作。

平台正式成立的标准不是功能数量，而是以下基础能够稳定运行：

- Search 与 Recommendation 可独立评估。
- Agent 按复杂度介入。
- 任务可计划、进入 `Waiting`（含原因）、恢复、取消和审计。
- 候选具有证据和 Rights 状态。
- 创作决策通过结构化 Artifact 交接。
- 媒体执行确定、可验证、可重放。
- 实际采用和最终保留能够回流优化。
