# 实施路线图与验收基线

> **状态：** Video Domain Agent 与跨域编排交付计划。
> **范围依据：** [交付范围与 Video/Clip 模型](00_交付范围与VideoClip模型.md)。
> **验收依据：** [纵向切片与验收脚本](06_VideoDomainAgent_纵向切片与验收脚本.md)。

## 1. 实施策略

按 Mock-first 顺序交付：

```text
Video/Clip 契约
  → Mock Catalog 与检索推荐
  → Runtime Agent
  → Creative Workflow
  → MaterialAssignment
  → Cross-domain Contract 与 Mock 领域
  → CreativeProductionWorkflow
  → Eval 与故障恢复
```

不建立真实数据加工、领域实现和索引的前置依赖。Mock Adapter 必须与未来真实 Adapter 共用 Port、Schema、事件和错误码。

## 2. 交付阶段

### 阶段 0：契约、数据库与 Mock Catalog

建议周期：1 周。

交付：

- Monorepo 与模块依赖。
- `Video -> Clip` JSON Schema 和 Java DTO。
- Project、Task、Step、Run、Artifact、ToolCall、Budget、Checkpoint 表，以及 Video/Clip Catalog 表；表结构以 [工程契约与研发 Backlog](05_VideoDomainAgent_工程契约与研发Backlog.md) §10 为准。`video_feedback_event` 放到阶段 1。
- Fake Video/Clip Fixture。
- Error、Idempotency 和 Event 基础设施。

退出标准：

- 固定 Video/Clip 数据可重复读取。
- Clip 时间区间校验通过，且 `duration_ms` 必须等于 `end_ms - start_ms`；时间不变量以 [交付范围与 Video/Clip 模型](00_交付范围与VideoClip模型.md) §2.2 为准。
- 迁移可正向和回滚执行。
- 跨租户约束测试通过。

### 阶段 1：Mock Search、Recommendation 与 Similar

建议周期：1–2 周。

交付：

- `RetrievalGateway` 的 Search、Recommendation、Similar 与 `writeFeedback`，以及 `video_feedback_event` 表。
- CandidateSet Schema。
- 零结果、超时和重复候选 Mock。
- `FakeEvidenceGateway`。
- Feedback 归因（经同一 `RetrievalGateway` 写入，不另拆检索 Port）。

退出标准：

- Search 可返回 Video/Clip。
- Clip 候选带父 Video、时间区间和证据。
- Recommendation 使用 Project 与 Clip context。
- Similar 不以 Seed 自身作为结果。
- Feedback 可写、可审计；Direct 路径允许 `task_id` 为空。Port 与表以 [工程契约与研发 Backlog](05_VideoDomainAgent_工程契约与研发Backlog.md) §7 / §10.9 为准。
- 同一输入和 Fixture 版本返回稳定排序。

### 阶段 2：Runtime 与 Video Domain Agent

建议周期：1–2 周。

交付：

- Runtime SDK Adapter。
- AgentSpec、Prompt 和输出 Schema。
- LocalToolset 的 Search/Recommend/Similar/Evidence Tool。
- Intent Router。
- Action、SSE、Run 回读和恢复。

退出标准：

- 简单 Search、Recommendation 和 Similar 不启动 Agent，直接走 Mock Port。
- 复杂任务创建固定版本 Agent Run。
- Tool 白名单和 Schema 校验有效。
- Caller Tool 完整批次可回传。
- SSE 断线和 Run 恢复通过。

### 阶段 3：Creative Workflow 与 Assignment

建议周期：2 周。

交付：

- TaskBrief、CreativeBrief、Storyboard。
- ClipPlan 与 ClipRequirement。
- 按计划槽位（`storyboard_clip_id`）并行检索（搜索与推荐）；素材 Clip 只作为分配对象。
- Composition、MaterialAssignment、替代和用户确认。
- 单个计划槽位（`storyboard_clip_id`）的局部替换。

退出标准：

- 复杂自然语言请求生成完整 Artifact 链。
- 每个计划槽位（`storyboard_clip_id`）有首选和替代。
- 修改 `sb_clip_003` 不重算其他 Assignment。
- Storyboard 只使用 `clip_requirements`。

### 阶段 4：Video Baseline Eval、安全与交付

建议周期：1 周。

交付：

- Agent Eval 固定集。
- 失败注入。
- 预算、Prompt Injection 和身份隔离测试。
- Demo、Runbook 和证据包。

退出标准：

- 验收脚本全部通过。
- 不依赖真实索引、媒体渲染和前端。
- 所有 Artifact 和 Tool 调用可追溯。

### 阶段 5：跨域契约、Artifact 与 Mock 领域

建议周期：1–2 周。

交付：

- `CreativeProductionWorkflow` 模块与 `DomainInvocationPort`。
- Cross-domain Task/Step、DomainInvocation、Artifact Index、依赖边和审批表。
- `campaign-brief`、`workflow-plan`、`product-context`、`landing-page-plan`、`copy-package`、`ads-draft`、`review-package` Schema。
- `FakeProductDomain`、`FakeLandingPageDomain`、`FakeCopyDomain`、`FakeAdsDomain`。
- Claim 来源、Artifact Envelope、领域错误和部分成功状态。

退出标准：

- 四个领域均可通过统一 Port 调用。
- 领域返回只包含 Artifact Ref、版本、状态、warning 和 usage。
- Video Agent 没有任何跨域 Tool 或依赖。
- 领域 Mock 支持成功、失败、超时、`needs_user_action` 和 stale 输入。

### 阶段 6：主 Workflow、审批与跨域验收

建议周期：2 周。

交付：

- CampaignBrief 和基于 `requested_outputs` 的 WorkflowPlan。
- Product → Video/Landing Page 并行 → Copy → Video/Landing Page 并行 → Ads 的执行图。
- fan-out、fan-in、部分成功、领域重试、取消、stale 传播和恢复。
- 范围化审批：Video Plan、Copy、Landing Page、Ads Draft、Publish。
- Video-only 与 cross-domain 双路径路由。
- 跨域 Eval、故障注入和 Mock Demo。

退出标准：

- `cross_domain_campaign` 不创建全能 Video Agent。
- 无依赖分支在某领域失败时仍可完成。
- 外部发布在未审批时始终被拒绝。
- Video-only 回归全部通过。
- [纵向切片与验收脚本](06_VideoDomainAgent_纵向切片与验收脚本.md)的跨域用例全部通过。

## 5. 测试体系

### 5.1 单元测试

- Video/Clip Schema。
- Clip 时间边界。
- Candidate 过滤与稳定排序。
- Assignment 约束。
- Task 状态迁移。
- Idempotency 和乐观锁。

### 5.2 契约测试

- Mock 与未来 HTTP Adapter 共用 Port Test。
- Tool 输入输出 Schema。
- Event Schema。
- SSE 和 Run 状态投影。

### 5.3 集成测试

- Agent → Tool → Mock Search / Recommendation / Similar。
- Storyboard → ClipPlan → CandidateSet → Assignment。
- User confirmation → Artifact version。
- Resume → original Run/Action。
- Workflow → DomainInvocationPort → Mock Product / Landing Page / Copy / Ads / Video。
- Cross-domain fan-out/fan-in、partial result、stale propagation 和审批。

### 5.4 Agent Eval

- 简单 Search、Recommendation 和 Similar 不启动 Agent。
- 信息不足时澄清。
- 复杂请求生成 ClipPlan。
- 零结果时有限重写。
- 替换或修改某个计划槽位（`storyboard_clip_id`）时只重算受影响范围。
- Prompt Injection 不越权。
- Tool 超时和预算耗尽。
- 跨域请求选择正确 Workflow。
- 领域失败不阻塞无依赖分支。
- Video Agent 不生成或调用其他领域 Artifact。
- Ads 草稿与发布审批分离。

## 6. 验收指标

本阶段先建立可重复基线，不承诺生产 SLO。

必须监控：

- Direct Search / Recommendation / Similar 不启动 Agent 的比例。
- Agent Task 完成率。
- Schema 校验通过率。
- Candidate 证据完整率。
- ClipPlan 覆盖率。
- Assignment 接受率和局部重算范围。
- Tool 成功率、调用次数和耗时。
- Waiting 恢复成功率。
- 跨租户泄漏，目标为 0。
- DomainInvocation 成功、部分成功和失败分类。
- Fan-out 并行度、fan-in 等待时间和领域重试率。
- Artifact stale 传播范围和误伤率。
- 跨域审批拒绝率和未审批发布拦截次数。
- Video-only 回归通过率。

## 7. 风险与应对

| 风险 | 应对 |
|---|---|
| 素材 Clip 与计划槽位混淆 | 使用 `storyboard_clip_id` 和独立 ID 命名空间；素材 Clip 只作为分配对象 |
| Mock 与真实实现分叉 | 共用 Port、Schema 和 Contract Test |
| Agent 滥用 Tool | 白名单、预算和 Action |
| 恢复重复执行 | requestId、toolCallId 和 Step 幂等 |
| 计划重新引入旧层级 | Schema 与 CI 禁止关键字 |
| 扩大为完整视频平台 | 以 00 范围基线为交付门禁 |
| 把跨域逻辑塞进 Video Agent | 主 Workflow + DomainInvocationPort 强约束；依赖测试 |
| 领域 DTO 跨边界传播 | 只允许 Artifact Ref、Envelope 和结果协议 |
| 部分成功被误判为完整成功 | ReviewPackage 显式列缺口并阻止 publish |
| Artifact stale 后仍被广告引用 | 发布前强制校验 ready/version/hash |

## 9. 推荐结论

先交付一个可稳定运行的 Mock Agent 闭环：

```text
自然语言
  → Video/Clip 检索或复杂任务
  → Storyboard / ClipPlan
  → Search / Recommendation
  → MaterialAssignment
  → 用户确认
```

Similar 是与 Search / Recommendation 并列的 Direct 能力，不一定走创作主链。该闭环通过后再替换真实 Retrieval Adapter。不得以补齐真实索引、渲染或前端作为本次开工前置。

随后交付跨域闭环：

```text
CampaignBrief
  → Product
  → Video / Landing Page 并行分析
  → Copy
  → Video / Landing Page 并行产出
  → Ads Draft
  → ReviewPackage
  → 范围化审批
```

主 Workflow 只通过 `DomainInvocationPort` 调用领域。Video Domain Agent 不被扩张为全能业务 Agent；真实领域实现和外部发布通过未来 Adapter 接入。
