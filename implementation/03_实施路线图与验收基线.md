# 实施路线图与验收基线

> **状态：** 通用 Video Domain Agent 交付计划。
> **范围依据：** [交付范围与 Video/Clip 模型](00_交付范围与VideoClip模型.md)。
> **验收依据：** [纵向切片与验收脚本](06_VideoDomainAgent_纵向切片与验收脚本.md)。

## 1. 实施策略

按 Mock-first 顺序交付：

```text
Video/Clip 契约
  → Mock Catalog 与检索推荐
  → Runtime Agent
  → Creative Workflow
  → MaterialAssignment
  → Eval 与故障恢复
```

不建立真实数据加工和索引的前置依赖。Mock Adapter 必须与未来真实 Adapter 共用 Port、Schema、事件和错误码。

## 2. 交付阶段

### 阶段 0：契约、数据库与 Mock Catalog

建议周期：1 周。

交付：

- Monorepo 与模块依赖。
- `Video -> Clip` JSON Schema 和 Java DTO。
- Project、Task、Step、Run、Artifact、ToolCall、Budget、Checkpoint 表。
- Fake Video/Clip Fixture。
- Error、Idempotency 和 Event 基础设施。

退出标准：

- 固定 Video/Clip 数据可重复读取。
- Clip 时间区间校验通过。
- 迁移可正向和回滚执行。
- 跨租户约束测试通过。

### 阶段 1：Mock Search、Recommendation 与 Similar

建议周期：1–2 周。

交付：

- Search、Recommendation、Similar Port。
- CandidateSet Schema。
- 零结果、超时和重复候选 Mock。
- Evidence Resolver Mock。
- Feedback 归因。

退出标准：

- Search 可返回 Video/Clip。
- Clip 候选带父 Video、时间区间和证据。
- Recommendation 使用 Project 与 Clip context。
- Similar 不以 Seed 自身作为结果。
- 同一输入和 Fixture 版本返回稳定排序。

### 阶段 2：Runtime 与 Video Domain Agent

建议周期：1–2 周。

交付：

- Runtime SDK Adapter。
- AgentSpec、Prompt 和输出 Schema。
- LocalToolset 的 Search/Recommend/Similar/Evidence Tool。
- Intent Router。
- Action、SSE、Run 回读和恢复。

退出标准：

- 简单 Search/Recommendation 不启动 Agent。
- 复杂任务创建固定版本 Agent Run。
- Tool 白名单和 Schema 校验有效。
- Caller Tool 完整批次可回传。
- SSE 断线和 Run 恢复通过。

### 阶段 3：Creative Workflow 与 Assignment

建议周期：2 周。

交付：

- TaskBrief、CreativeBrief、Storyboard。
- ClipPlan 与 ClipRequirement。
- 并行 Clip 搜索与推荐。
- Composition、MaterialAssignment、替代和用户确认。
- 单个计划 Clip 的局部替换。

退出标准：

- 复杂自然语言请求生成完整 Artifact 链。
- 每个计划 Clip 有首选和替代。
- 修改 `sb_clip_003` 不重算其他 Assignment。
- Storyboard 只使用 `clip_requirements`。

### 阶段 4：Eval、安全与交付

建议周期：1 周。

交付：

- Agent Eval 固定集。
- 失败注入。
- 预算、Prompt Injection 和身份隔离测试。
- Demo、Runbook 和证据包。

退出标准：

- 验收脚本全部通过。
- 不依赖真实索引、媒体渲染和前端。
- 所有 Artifact 和 Tool 调用可追溯。

## 4. 启动顺序

### Day 1

- 冻结 `Video -> Clip` Schema。
- 冻结 `ClipPlan / ClipRequirement`。
- 冻结 Mock Fixture。

### Day 2–3

- 建 Project/Task/Artifact 表。
- 实现 Fake Video Catalog。
- 实现 Search/Recommend/Similar Port。

### Day 4–5

- 接入 Runtime SDK 和 Fake Runtime。
- 发布最小 Video Domain AgentSpec。
- 验证 LocalToolset 和 Action。

### Day 6–8

- 实现 Storyboard、ClipPlan 和 Clip 级并行检索。
- 实现 Composition 和 Assignment。

### Day 9–10

- 实现局部替换、预算、恢复和 Eval。
- 运行纵向验收。

## 5. 测试体系

### 5.1 单元测试

- Video/Clip Schema。
- Clip 时间边界。
- Candidate 过滤与稳定排序。
- Assignment 约束。
- Task 状态迁移。
- Idempotency 和乐观锁。

### 5.2 契约测试

- Mock 与未来 HTTP Adapter 共用 Port Test。
- Tool 输入输出 Schema。
- Event Schema。
- SSE 和 Run 状态投影。

### 5.3 集成测试

- Agent → Tool → Mock Search/Recommendation。
- Storyboard → ClipPlan → CandidateSet → Assignment。
- User confirmation → Artifact version。
- Resume → original Run/Action。

### 5.4 Agent Eval

- 简单搜索不启动 Agent。
- 信息不足时澄清。
- 复杂请求生成 ClipPlan。
- 零结果时有限重写。
- 单 Clip 局部替换。
- Prompt Injection 不越权。
- Tool 超时和预算耗尽。

## 6. 验收指标

本阶段先建立可重复基线，不承诺生产 SLO。

必须监控：

- Direct Search 不启动 Agent 的比例。
- Agent Task 完成率。
- Schema 校验通过率。
- Candidate 证据完整率。
- ClipPlan 覆盖率。
- Assignment 接受率和局部重算范围。
- Tool 成功率、调用次数和耗时。
- Waiting 恢复成功率。
- 跨租户泄漏，目标为 0。

## 7. 风险与应对

| 风险 | 应对 |
|---|---|
| Clip 与计划 Clip 混淆 | 使用 `storyboard_clip_id` 和独立 ID 命名空间 |
| Mock 与真实实现分叉 | 共用 Port、Schema 和 Contract Test |
| Agent 滥用 Tool | 白名单、预算和 Action |
| 恢复重复执行 | requestId、toolCallId 和 Step 幂等 |
| 计划重新引入旧层级 | Schema 与 CI 禁止关键字 |
| 扩大为完整视频平台 | 以 00 范围基线为交付门禁 |

## 8. 实施决策

| ID | 决策 |
|---|---|
| IMPL-ADR-01 | Runtime Java SDK 是 Agent 接入契约 |
| IMPL-ADR-02 | 领域模型固定为 Video / Clip |
| IMPL-ADR-03 | Mock Search/Recommendation 先于真实 URRE |
| IMPL-ADR-04 | Simple Query 不经 Agent |
| IMPL-ADR-05 | Storyboard 使用 ClipRequirement |
| IMPL-ADR-06 | Assignment 绑定候选 Video/Clip |
| IMPL-ADR-07 | Task 状态由业务 Workflow 持有 |
| IMPL-ADR-08 | Tool 与 Action 全链路审计 |
| IMPL-ADR-09 | 媒体执行和真实索引不在本次交付 |
| IMPL-ADR-10 | 所有 Adapter 共享 Schema 与 Contract Test |

## 9. 推荐结论

先交付一个可稳定运行的 Mock Agent 闭环：

```text
自然语言
  → Video/Clip 检索或复杂任务
  → Storyboard / ClipPlan
  → Search + Recommendation
  → MaterialAssignment
  → 用户确认
```

该闭环通过后再替换真实 Retrieval Adapter。不得以补齐真实索引、渲染、前端或跨领域业务作为本次开工前置。
