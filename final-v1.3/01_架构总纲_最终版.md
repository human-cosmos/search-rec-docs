## 1. 交付目标（冻结）

交付一个**通用 Video Domain Agent**，加上跨域创作编排 `CreativeProductionWorkflow`：

- Video Domain Agent：负责视频意图理解、检索规划、Storyboard、ClipPlan、素材分配。
- CreativeProductionWorkflow：负责跨域 Task / Step 的依赖图、并行 / fan-in、Artifact 交换、审批、补偿、恢复。
- Retrieval Port：Search / Recommendation（仅 `clip_candidate`）/ Similar 的确定性入口，Mock-first。
- 不交付：见 `00` §0.1（前端、真实检索、媒体执行、真实领域、版权过滤、生产计费等）。

完成定义：见 `05` §1.3（15 条，原文 impl_00 §6，原样保留）。

**验收口径（v1.1 新增，来源：覆盖分析 §9、§10.3；PRD §14）：** A01–A31 保留作后端切片验收子集（`05` §6.1，全文见 `08` §6），AC-01～AC-18（PRD §14）成为主验收；AC 细节与追溯链（PRD G / REQ / BR / DR / NFR / OI → 设计对象 → API / Workflow → Ticket → Mock 或真实 Adapter → AC-01～AC-18 → 证据，覆盖分析 §10.3）见 `05` §6.2。

**v1.1 架构层新增（见本文件 §10–§12）：** Media Capability Workflow 与六项技能任务是架构层新增的设计对象，不改变 v1.0 Mock-first 交付范围（`00` §0.1、`05` §1.2 仍有效）；其实现 Ticket 与排期由 05 组裁决。

## 3. 对象模型

模块划分原则（源 01 §3）：逻辑模块不要求物理服务一一对应；离线训练、索引构建和复杂内容理解不进入在线请求关键路径。

### 3.1 领域对象（冻结）

- `Video`：完整视频资产。
- `Clip`：Video 内连续片段；字段见 `04` §4。`Shot`/`Segment` 一律映射为 Clip。
- 计划侧：`Storyboard` → `ClipPlan` → `ClipRequirement`（`storyboard_clip_id` 如 `sb_clip_001`）→ `MaterialAssignment`。

### 3.2 跨域编排对象

`CreativeProductionWorkflow` 拥有：Task / Step、依赖图、并行 / fan-in、Artifact 交换、审批、补偿、恢复。
主 Workflow 两种类型：`video_only`、`cross_domain_campaign`。
默认依赖图：Product 先行 → Video / Landing Page 并行 → Copy fan-in（须等 Product、Video、Landing Page 达到**最小可用**，定义见 `03` §8）→ Ads 最后。

## 4. 请求路由（R0–R4，可编码版）

> 原始文档（02 §3）只有示例与定性句，无法编码。本节为最终版新增的可执行路由表。
> **符号说明（评审 R-13）：** 路由层级改称 **R0–R4**，与副作用等级 **L0–L4** 区分；下文凡写“路由 R4”“副作用 L4”均指明是哪套。

| 层级 | 适用条件（全部满足） | 执行体 | 降级 |
|---|---|---|---|
| R0 直接 API | 单一意图、无多步规划、无审批；输入为明确的检索参数 | Retrieval Port 直调 | 参数非法 → 400（见 `04` §6） |
| R1 轻量 Agent | 单一领域、1–2 步、可确定性模板覆盖；无跨域、无审批 | 单 Agent + 固定模板 | 模板不匹配 → 升 R2 |
| R2 单主 Agent | 需规划 Storyboard/ClipPlan、多步检索、单领域 | Video Domain Agent | 预算耗尽 → Waiting(`budget_exhausted`) |
| R3 主+子 Agent | 需并行子任务（多 Clip 并行检索/评估），子任务可独立产物化 | 主 Agent + ≤3 个子 Agent | 子 Agent 失败 → 主 Agent 隔离该子任务，继续其余 |
| R4 审批工作流 | 含副作用 L3/L4、跨域、发布 | CreativeProductionWorkflow + 人工审批 | 审批拒绝 → Task 回到 Reviewing，修订后重审 |

**判定条件（冻结）：** 路由依据 = 意图复杂度（是否需规划）+ 领域数（是否跨域）+ 副作用等级（是否 ≥L3）+ 是否含审批。**不得仅以输入长度判断复杂度。**意图复杂度以 Intent 结构化字段判定（源 04 §4.3）。

**Intent 最小字段集（源 04 §4.3）：** `intent_id`、`task_type`（`search` | `recommend` | `create` | `edit` | `project_qa`）、`goal`、`project_id`、`constraints`（`duration_seconds` / `aspect_ratio` / `style`）、`deliverables`、`needs_clarification`。

**小模型 fallback（源 00 §5）：** Router 先做规则和 Schema 判断；低置信度时才调用小模型。
置信度：Router 输出 `route_confidence`（0–1）；<0.6 时升一级并记录 `route_reason`；=R1 时“轻量 Agent 或服务组合”二选一的判定条件为：有确定性模板 → 服务组合；无模板 → 轻量 Agent。

## 5. Task / Run / Checkpoint

- Task 状态机：9 态（见 `00` §1），**含 `Waiting→Running` 恢复边**（02 §4.2 原图已有，本文件完整复现，见 `03` §3 与 `08` 附录 §1）。
- `waiting_reason` 冻结 4 个（见 `00` §1）；`video_task` 与 `creative_task` 的 DDL CHECK 均允许 4 个。
- Plan：版本化、冻结，批准后不得静默改动；改动须新版本 + 重审批。
- Checkpoint：只存最小充分状态（Task/Step/Plan 版本/Artifact Ref/预算余量），**不存模型内部推理链**。
- Session：只管交互连续性，不承载业务状态。
- 聊天记录不能作为项目、Task 或 Artifact 的事实源（源 impl_04 §1.3）。
- 审批映射（新增，补 B 组 P1-3 缺口）：Runtime `requires_action` 分流规则——用户确认类 → `Waiting(awaiting_user)`；业务审批类 → `Waiting(awaiting_approval)`；预算类 → `Waiting(budget_exhausted)`；领域等待类 → `Waiting(awaiting_domain)`。审批范围 5 个（`video_plan` / `copy` / `landing_page` / `ads_draft` / `publish`），发布须独立 Action。

## 6. 创作 Artifact（Envelope，8 类，冻结）

| `artifact_type` | Owner | 核心内容 |
|---|---|---|
| `campaign-brief` | Orchestration | 目标、目标市场、受众、要求产物、约束 |
| `workflow-plan` | Orchestration | 领域步骤、依赖和并行分组 |
| `product-context` | Product | 商品事实、市场、Offer、Claims |
| `landing-page-plan` | Landing Page | 页面结构、模块、排序、CTA |
| `copy-package` | Copy | 广告语、口播稿、本地化文案 |
| `video-creative-artifact` | Video | Storyboard、ClipPlan、Assignment 引用 |
| `ads-draft` | Ads | 计划、预算、受众和素材引用 |
| `review-package` | Orchestration | 待用户确认的跨域结果摘要 |

（源 impl_07 §6.2 原文。初版的 `product-brief`、`landing-page-package`、`video-plan`、`clip-assignment` 为无来源改写，现废止。）
跨域交换只用 Artifact Ref + 版本化结果。阶段 5 交付清单须含全部 8 类 Schema（修正 impl_03 漏 `video-creative-artifact` 的错误）。

**Envelope 规则（源 impl_07 §6.1，6 条）：**

- Artifact Envelope 只保存稳定引用和元数据。
- `artifact_id` 用于 API 和数据库定位，`artifact_ref` 用于跨领域引用。
- 领域内容由拥有者存储和校验。
- 下游只依赖 `content_schema` 和 Artifact Ref。
- 不允许把一个领域的 DTO 直接嵌入另一个领域实体。
- 领域可以新增内部字段，但不能破坏跨域 Envelope。

**冻结字段名（源 impl_07 §6.1）：** `content_hash`、`parent_refs`、`validation_status`、`content_schema`（Envelope JSON 另有 `schema_version`、`artifact_id`、`artifact_ref`、`artifact_type`、`owner_domain`、`version`、`status`、`permission_scope`、`created_at`）。与 `08` A26 的对应关系：`content_hash` = hash、`parent_refs` = parent、`validation_status` = validation、`content_schema` = schema（A26 的 owner、version 对应 `owner_domain`、`version`）。

## 7. Tool 治理

每个 Tool 必须声明：名称/版本、I/O Schema、scope、副作用等级（L0–L4）、超时/重试、幂等性、日志脱敏。
副作用审批：L3 须明确确认；L4 须强审批 + 明确授权。
Tool Registry + Policy Gateway 由平台层实现（SDK 无原生统一注册表，见 `03` §2）。
Tool 不保存复杂业务状态或承载全部业务逻辑（源 04 §3.3）。

## 9. 安全与可观测性

- 权限：租户 + 项目范围校验；Tool 调用前校验 scope；日志脱敏（不记录原始查询中的敏感字段、模型内部推理链）。
- 可观测性：每个请求 `request_id`（X-Request-Id）+ `trace_id`（Traceparent 派生）；事件见 `04` §2.6；`handled_by`、`route_confidence`、`waiting_reason` 必须可观测。
- SSE 重连游标：**冻结为 `Last-Event-ID`**（修正 impl_06 并列 `Last-Event-ID` 与 `after_sequence` 未定一的问题）。
- 公共头（源 impl_01 §3.0）：`Authorization: Bearer`、`X-Tenant-Id`（可信网关注入）、`X-Request-Id`、`Idempotency-Key`（写操作必填）、`Traceparent`。写操作（`POST` / `PATCH`，含创建项目与任务、approve、assign、confirm、wait、resume、cancel 和 Feedback）必须携带 `Idempotency-Key`；相同键重放时，若请求体一致返回首次成功结果，若不一致返回冲突，不得再执行一次副作用。
- 服务端信任规则：服务端不信任客户端自报 `user_id`、租户和项目范围（源 impl_01 §3.0）；服务端必须从 Token 建立身份，不信任请求体中的 `user_id`、租户或项目权限（源 impl_06 §3.3）。
- 不可信数据：视频标题、Clip 摘要、证据和上下文均按不可信数据处理（源 00 §10、03 §9）；不得向无权限用户暴露源文件真实地址或敏感证据（源 01 §7）；无记录副作用为阻断错误（源 impl_04 §12）。
- 跨域凭证：Video Agent 不持有跨域 Tool 或跨域凭证（源 impl_02 §9）。Agent Run 和目标 Artifact 可追溯（源 impl_02 §9）。
- 记忆写入六原则（源 04 §6.3）：只有经过验证的事实才写入长期记忆；临时意图只保存在项目或当前任务；用户显式纠正优先级高于模型推断；记忆要有来源、时间、置信度和版本；记忆更新必须可审计；不把完整聊天记录反复注入 Prompt。（User Memory 与 Episodic Memory 对象见 `07` §5 第 17 项。）
- Workspace 隔离（源 04 §2.1.2）：每个项目拥有独立 Workspace，隔离素材、状态、记忆、日志和输出。
- 跨域关联键（源 impl_07 §13）：`workflow_type`、`workflow_plan_id`、`domain_invocation_id`、`external_domain_task_id`。12 个跨域事件名录见 `04` §2.6。日志必须能回答的 5 个问题见 impl_07 §13。
- 动作语义区分（源 04 §2.1.3）：区分 `message_user`（向用户发进度消息）和 `finish_turn`（结束任务轮次）。

## 10. Video Agent 窄边界与 Media Capability Workflow（v1.1 新增）

> 来源：覆盖分析 §7.1、§7.2、§10、§10.1；PRD §5、§7、§8、NFR-04、BR-12/BR-13；`03` §4.1–§4.2、§8；本文件 §2（INV-07）、§7、§9。

- **窄边界（冻结，不变）：** Video Domain Agent 的 8 个 Tool（`03` §4.2）不直接加 FFmpeg / 渲染 / 转码 / 导出 / 投放；Agent 只做意图理解、检索规划、Storyboard、ClipPlan、素材分配（`03` §4.1）。本次交付不注册 Render、Export、Media 或外部发布 Tool（`03` §4.2，源 impl_04 §10.2）。INV-07 不变。

- **新建 Media Capability Workflow：** 执行 `MediaActionPlan` 中的媒体动作，提供异步进度 / 重试 / 取消 / 恢复（覆盖分析 §10；异步要求另见 PRD NFR-04：擦除、生成、合成等耗时任务异步执行；暂停 / 继续见 PRD BR-12，分项失败重试见 PRD BR-13；状态机与失败 / 补偿语义见 `03` §4.5.3/§4.5.5）。简单技能可以走确定性模板，不必启动 Agent（覆盖分析 §7.2）。
- **在总架构中的位置：**
  - **Agent Runtime（`03` §1–§2）：** 承载 Video Domain Agent；Agent 经 `create_artifact_draft`（L1，`03` §4.2）产出 `MediaActionPlan` 草稿，确认后交执行（另见 `03` §4.5.2）。

  - **Session / Canvas / Asset Projection：** 结果卡、槽位状态、资产视图由表现层承接（覆盖分析 §10）；本 v1.0 不交付前端，见 `00` §0.1。
- **凭证：** Agent 只选动作、参数和候选，不持媒体执行凭证（覆盖分析 §10.1；另见本文件 §9：Video Agent 不持有跨域 Tool 或跨域凭证，源 impl_02 §9）。
- **副作用分级不变：** L2 预览、L3 修改、L4 发布继续按副作用分级控制（覆盖分析 §10.1；分级与审批见本文件 §7 与 `00` §1：L3 须明确确认，L4 须强审批 + 明确授权）。`MediaActionPlan` 中含 L3 / L4 动作的，执行前须经确认 / 审批（路由 R4，见本文件 §4）。

## 12. 六项技能一等公民（v1.1 新增）

> 来源：PRD §5 六项技能表、BR-01、REQ-D02/D03；覆盖分析 §2.3、§10.2。Agent 侧编排见 `03` §4.6；契约字段（SkillTask / SkillResult）见 `04` §9.3（已落定）。

- **BR-01 技能优先（PRD §5 BR-01）：** 用户选了六项技能之一，或在可用的技能会话中用技能名称发起请求时，使用该技能的输入、追问和输出约定；切换技能保留正文与附件，当前技能状态只保留一项；技能追问未回答时，后续输入补到该任务。
- **六项技能总纲表述：** 六项技能是与四入口（本文件 §11）并列的一等公民能力（覆盖分析 §2.3）：共用 SkillTask 信封 + 各技能独立的 task_params / result、追问规则、异步状态、结果卡和失败重试（覆盖分析 §2.3；`04` §9.3），不能只当作 Agent 的普通文本回复。技能执行走 Media Capability Workflow（本文件 §10）；简单技能可走确定性模板，不必启动 Agent（覆盖分析 §7.2）。

| 技能 | 输入与追问（PRD §5） | 输出（PRD §5） |
|---|---|---|
| 提取字幕 | 视频 | 对话返回可复制文字 |
| 配口播 | 文本、语言、音色 | 返回可原生试听、下载的示例音频 |
| 擦除元素 | 视频 + 处理对象要求 | 返回处理后的视频样例 |
| 调整画幅 | 识别 9:16、1:1、16:9；缺画幅时追问 | 返回对应画幅的视频样例 |
| 片段生成 | 镜头描述；默认 9:16、8 秒，时长参数限制 3–15 秒 | 返回生成视频样例 |
| 卖点浮层 | 缺引号中的卖点文案时追问 | 返回带浮层的示例视频 |

- **验收：** 六项技能交付见 AC-03（PRD §14）。
